# Brief — Order lesson homes so the harness compounds

Task: Order lesson homes so the harness compounds · Lap: temp_job_lesson-home-ladder · Harness: v0.44.0

## Problem
`meta-learn-lessons` picks a lesson's home from a topic table only, so lessons default to prose in always-on rules or skills (context grows every lap), mechanical lessons are not proven to be enforced, and lessons that improve the harness itself never leave this repo.

## Success check
Given a lesson that an existing validator or lint rule can hold, `meta-learn-lessons` writes or tightens that check (proved by seeing it fail on the defect shape) and adds no prose; given a lesson about one area, it uses a path-scoped rule rather than an always-on rule; and its report line states the lesson's scope (`repo` or `harness`).

## Owner test
none — harness skills only; nothing changes in the app.

## In scope
- A cheapest-first **home ladder** in `meta-learn-lessons` (owner: `references/lesson-procedure.md` § 3; `SKILL.md` step 5 points to it). First tier that holds wins:
  1. **One way** — the mistake was possible because two ways exist → report a consolidation as a `Foundation:` task (no product-code change from this skill).
  2. **Check** — validator, lint rule, structure/arch config, or test that catches the defect. Kept only after it passes on the current tree and fails on the defect shape in a throwaway copy (never in the working tree). Config files are protected → the owner yes in chat this skill already asks covers it.
  3. **Path-scoped rule** — a `.claude/rules/<name>.md` with `paths:` (new or existing) when the lesson applies to one area of files. Loads with no decision to read.
  4. **Always-on rule or skill edit** — only when the lesson must shape work before any file is touched (planning, scoping, asking). State why tiers 2–3 can't hold it; every later session pays for this line.
  5. **Note in a home with a fixed reader** — a feature `README.md` (read at `loop-refine` step 2) or `spec-debug-runtime/references/patterns.md` (searched at debug intake). No new notes store.
  The existing topic table stays as the "which file within the tier" lookup.
- **Narrowing a wrong skill or rule** stays the removal-first path (reverse audit); the ladder applies to what is added.
- **Scope tag** on every persisted lesson: `repo` (true only for this app/repo) or `harness` (would help any fork of this harness). Recorded in the report line and as a commit trailer `Lesson-scope: harness|repo` on the commit that carries the lesson.
- `meta-write-adoption-guide`: for a harness-change guide, collect `git log --grep='Lesson-scope: harness'` since the last guide on that topic as candidate content.
- One eval case under `.agents/skills/meta-learn-lessons/evals/` encoding the success check.
